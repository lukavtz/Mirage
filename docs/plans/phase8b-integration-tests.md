# Phase 8b: Integration Tests — Plan

**Цель:** 8 интеграционных тестов, проверяющих полный пайплайн Mirage Stealer.
**Оценка:** ~1 день

---

## Структура тестов

### test_runner.zig — основной файл

Каждый тест — функция, вызываемая из `main()`. Результаты выводятся в консоль.

### Тесты

#### 1. Full Pipeline (collect → archive → encrypt → send → panel receives)

**Что проверяет:** Весь пайплайн от сбора данных до отправки на панель.

**Как тестировать:**
1. Создать тестовую директорию с фейковыми профилями браузеров
2. Запустить `buildReport()` с env vars, указывающими на тестовую директорию
3. Проверить что `report.len > 0`
4. Создать ZIP архив
5. Зашифровать ChaCha20-Poly1305
6. Расшифровать обратно
7. Проверить что расшифрованные данные совпадают с оригиналом

**Не требует:** сети, реальной панели

#### 2. Size Check (< 150 KB)

**Что проверяет:** Размер ReleaseSmall бинарника.

**Как тестировать:**
1. Проверить что `zig-out/bin/Mirage.exe` существует
2. Проверить что размер < 150 KB

**Требует:** собранного бинарника

#### 3. Static Check (Windows Defender scan)

**Что проверяет:** Обнаруживаемость Defender'ом.

**Как тестировать:** Запустить `MpCmdRun.exe -Scan -ScanType 3 -File .\Mirage.exe`
**Примечание:** Тест чисто информационный, не влияет на прохождение пайплайна

#### 4. Cross-Module (all collectors run without crashing)

**Что проверяет:** Все модули сбора отрабатывают без паники.

**Как тестировать:**
1. Вызвать `chromium.collect()` с фейковым путём
2. Вызвать `firefox.collect()` с фейковым путём
3. Вызвать `wallets_mod.collect()` с фейковым путём
4. Вызвать `messengers_mod.collect()` с фейковым путём
5. Вызвать `gaming_mod.collect()` с фейковым путём
6. Вызвать `system_info.collect()`
7. Убедиться что ни один не паникует

#### 5. Memory Leak Check

**Что проверяет:** Все аллокации освобождены.

**Как тестировать:**
1. Запустить сбор данных
2. Замерить память до и после через `NtQuerySystemInformation`
3. Разница не должна расти при повторных запусках
4. Использовать `std.heap.GeneralPurposeAllocator` с проверкой утечек

#### 6. Error Isolation

**Что проверяет:** Ошибка в одном модуле не убивает весь процесс.

**Как тестировать:**
1. Вызвать модуль, который должен упасть (например, передать невалидные данные)
2. Убедиться что `catch` отработал и вернул пустой результат
3. Процесс продолжает выполняться

#### 7. Network Timeout

**Что проверяет:** Таймаут 15 секунд на сетевые запросы.

**Как тестировать:**
1. Попытаться подключиться к несуществующему хосту
2. Замерить время подключения
3. Убедиться что таймаут наступил за < 20 секунд

#### 8. Panel End-to-End

**Что проверяет:** Панель принимает лог, сохраняет в SQLite, возвращает статистику.

**Как тестировать:**
1. Запустить PanelServer на тестовом порту
2. Отправить тестовый лог через HTTP POST
3. Запросить статистику через HTTP GET
4. Убедиться что данные появились
5. Остановить PanelServer
